# めも2

基礎のCRUDはStep1で完了。

目標: 本格的なAPIアプリ+フロント/バックエンド分離

## ロードマップ

### 1 REST設計の深堀(応用編)

- ネストリソース(`dogs/{dog}/walks`)
- ページネーション
- ソート・フィルタリング
- HTTPステータスコードの使い分けを学ぶ

=> 現在のDog APIにWalkリソースを追加するのが一番の実践

### 2 APIレスポンスの整形(LaravelのAPI Resource)

現在は、`return $dog;`でモデルをそのまま返している。

実務では、`Illuminate\Http\Resources\Json\JsonResource`を使って、

「レスポンスの形を意図的に整形する」という層を持たせるのが一般的。

不要なカラムを隠したり、リレーションを含めたりする際に必須の知識。

### 3 OpenAPI(Swagger)の基礎

「API仕様書」を標準化されたYAML/JSON形式で書く方法。

Dog APIを実際にOpenAPI仕様書として書き起こし、Swagger UIでブラウザ上に表示してみる。

将来的にフロントと分離する際、この仕様書が両者の契約書になる。

### 4 認証・認可の事務設計を一歩進める

現在は、User登録・ログインのmanagerがない状態。

ユーザー登録・ログイン・ログアウトのエンドポイントを自前で実装する必要がある。

パスワードハッシュ化やレートリミットなども登場。

### 5 フロントエンドとの連携(Vue/Reactなど)

SPA認証で学んだSanctumの知識を実際に使うフェーズ。

フロントを別リポジトリで立ち上げ、CORS設定やCookieドメインの設定など。
